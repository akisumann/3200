# 正典（カノン）の扱い

## status の4段階

すべての `world/` 配下のファイルは、frontmatter に `status` を持つ。

| status | 意味 | 他所から参照してよいか |
|---|---|---|
| `draft` | 名前と断片だけ。思いつきの置き場 | 参照可。ただし内容は当てにしない |
| `wip` | 書きかけ。方向は決まっているが未完 | 参照可 |
| `canon` | **確定**。作品を作るときの前提にしてよい | 参照可 |
| `dropped` | 没。もう使わない | **参照しない**（`check.py` が警告する） |

## なぜ4つあるか

「完成に近い世界設定がある」状態でも、実際には項目ごとに固まり具合が違う。全部を同じ扱いにすると、二種類の事故が起きる。

1. **固まっていないものを前提に作品を作ってしまう** — 後で設定が変わり、作った物が壊れる
2. **固まっているのに、変わるかもしれないと思って使えない** — 手が止まる

`status` はこの境界を明示するためだけにある。**`canon` を付けたものは、以後うかつに変えない**という自分への約束が本体。

## canon を変えたくなったら

変えてよい。ただし手順を踏む。

1. `tools/check.py` を実行し、その ID を参照している箇所を洗い出す
2. 参照元の記述が矛盾しないか確認する（`projects/` 以下も含む）
3. 変更内容と理由をコミットメッセージに書く

`git log -- world/characters/aria.md` で、その項目が「いつ・なぜ変わったか」を後から追える。これが正典を git で管理する一番の利点なので、コミットメッセージは丁寧に書く価値がある。

## dropped の扱い

没にしたものは**削除せず** `status: dropped` に変える。

- 削除すると、なぜ没にしたかが失われ、数か月後に同じ案を思いついて同じ理由で没にすることになる
- 本文の末尾に `## 没理由` を足しておくと、その再発を防げる
- どうしても消したくなったら消してよい。git 履歴には残る

## 曖昧なままにしておく権利

**すべてを決める必要はない。** 決めていないことは `## 未決` 節に書いて放置してよい。

未決を潰さないまま先に進めるのは悪いことではなく、むしろ「決めなくても作品が作れる」ことの確認になる。作品を作る過程で必要になったものだけ決めれば、決めた設定が必ず使われる。逆に、使われる当てのない設定を先回りして全部決めると、その大半は死蔵される。
